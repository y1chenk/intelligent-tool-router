# Routing examples and counterexamples

| Request/state | Appropriate next step | Completion limit |
| --- | --- | --- |
| Greeting or simple arithmetic | Answer directly. | No tool/other skill required. |
| Current API docs already sufficient in the primary reader | Use those current official results. | Extra general search needs a concrete gap or host requirement. |
| Failed deployment | Engineering route; inspect exact deployment logs/config. | Tool availability does not authorize redeploy. |
| Three URLs copy one release statement | Deduplicate to one evidence root. | Attribute the single source; no invented corroboration. |
| Removed scientific download | Research route; exact filename/project/release/archive pivots. | Historical snapshot does not establish current availability. |
| One branch exhausts three distinct queries | Close that branch; explore a relevant untried alternative. | No endless reopening of the same exhausted identifier. |
| Validation fails because a pre-existing lint error remains | Inspect causal fit before restoring any change. | Do not erase a good fix or unrelated user edits. |
| Failed owned edit with concurrent user changes | Restore only the owned delta when safe, verify it. | Unsafe restoration blocks further mutation on that target. |
| Approved email timed out | Inspect send state before deciding to retry. | Existing approval stands; avoid duplicate sends. |
| Future scheduled task | Verify the intended future time and timezone. | Future date is not an entity/date mismatch. |
| Running authorized job is pending | Poll by the tool contract. | Soft budgets do not cancel required polling. |
| Package created, no installed status | Report package-created/saved state. | No claim of installation or mobile auto-trigger reliability. |
